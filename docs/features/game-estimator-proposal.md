# F-GameEstimator: 模拟发牌机制与玩家视角估值器

> Status: proposal | Owner: @小捷 | Reviewer: TBD

## Why
铲屎官指出我们需要基于全新方向，构建一个“模拟游戏发牌机制 + 提供博弈依据的估值器”，而不是重构旧有代码。我们的目标是建立一套可以从“上帝视角”生成底牌，再从“玩家视角”推算期望收益的博弈分析模型。

## What (架构设计方案)

该系统主要分为三个解耦的核心模块：

### 1. 发牌机制模拟器 (Dealing Simulator)
负责从**上帝视角**生成绝对真实的“底牌”（Hidden State）。
- **底池与权重引擎**: 读取配置（如物品清单、掉落概率、稀有度权重），基于随机种子生成物品集合。
- **空间与约束生成**: 如果游戏带有空间排布限制（例如暗区/塔科夫的网格系统），该引擎会进行 2D/3D 碰撞装箱排列，生成合法的物理/格子状态。
- **输出**: 一个包含所有物品绝对属性、位置、总价值的完整 State 对象。

### 2. 玩家视角信息提取器 (Player Knowledge Extractor)
模拟“战争迷雾”，负责把“上帝视角的底牌”降维过滤为玩家能看到的“线索”。
- **信息遮蔽**: 隐藏具体的物品种类和精确位置。
- **线索透出**: 只暴露如“总占格面积”、“物品总数量”、“已知的特定边界形状”、“总体均价（如果有类似拍卖行的预估）”等宏观限制条件。
- **输出**: 一个 `Observation` 对象，代表当前玩家在这一局/这个盲盒面前所掌握的所有已知信息。

### 3. 博弈估值器 (Game-theoretic Estimator)
核心大脑，负责在信息不全的情况下，基于 `Observation` 进行反向求解与期望值（EV）估算。
- **先验知识库 (Prior)**: 知道游戏所有可能的物品列表和掉率。
- **合法状态穷举 (Constraint Solver)**: 利用 2D 背包算法或穷举算法，推算出所有同时满足 `Observation`（特定面积、特定件数）的物品组合。
- **概率与期望计算**: 对所有合法的组合，基于先验掉率计算后验概率（Bayesian Posterior），并求出最终的数学期望值。
- **防状态爆炸降级**: 当潜在合法组合过多时（例如超过特定算力预算），自动降级为“流体均值估算”，放弃硬性拼图检查，仅保留面积体积层面的统计估值。
- **输出**: 提供决策依据（当前盲盒的 EV 值、最高可能价值、极品爆率、建议博弈价格）。

## Acceptance Criteria
- [ ] AC-1: 能独立运行一局模拟生成（Mock Dealing），输出完整暗箱数据。
- [ ] AC-2: 能将暗箱数据过滤为玩家观测态（Observation）。
- [ ] AC-3: 估值器能接受 Observation，并在设定的超时时间（如 500ms）内返回 EV 估值。
- [ ] AC-4: 拥有应对状态爆炸的防卡死降级策略。
